3. Prior Authorization Adjudication & Signing Sequence

Clinical Execution Trace

Sequence trace from note extraction, deterministic evaluation, 4-digit PIN authorization, cryptographic block creation, and clearinghouse submission.

sequenceDiagram autonumber actor Clinician as Attesting Clinician participant UI as CarePolicyGuard Frontend participant API as FastAPI Gateway participant NLP as Clinical NLP Engine participant Rules as CMS Policy Matcher participant DB as Relational Database participant Audit as Cryptographic Ledger Engine participant MAC as CMS Medicare MAC Gateway Clinician->>UI: Selects patient case or triggers CDS Hooks order-sign UI->>API: POST /api/v1/adjudicate (EHR notes, policy_id, patient_id) API->>DB: Query MedicarePolicy and criteria (eager selectin batch) DB-->>API: Policy criteria definitions API->>NLP: Extract clinical entities, biomarkers, and temporal spans NLP-->>API: Extracted structured clinical facts API->>Rules: Evaluate criteria (inclusions, exclusions, thresholds) Rules-->>API: Decision (APPROVED / DENIED / DEFERRED), confidence, and citations API-->>UI: Return adjudication recommendation with evidence highlights Clinician->>UI: Reviews clinical justification and clicks "Sign and Authorize" UI->>Clinician: Prompts 4-Digit Clinician Signing PIN modal Clinician->>UI: Enters 4-Digit Signing PIN UI->>API: POST /api/v1/adjudicate/sign (case_id, PIN, attestation) API->>Audit: Compute SHA-256 cryptographic hash and link previous block Audit->>DB: Store immutable AdjudicationLog entry API->>MAC: Transmit 278 Prior Authorization claim via PAS MAC-->>API: Return Payer Transaction ID (CMS-MAC-ACK) API->>DB: Update submission_status = SUBMITTED, payer_transaction_id API-->>UI: Return signed confirmation with verification seal UI-->>Clinician: Display transmission receipt and cryptographic hash

4. MFA & Live Email OTP Delivery Sequence

Security & Identity Verification

Step-up two-factor verification with live Google SMTP TLS delivery and ephemeral passcode validation.

sequenceDiagram autonumber actor User as Healthcare User participant Browser as Browser Client participant AuthAPI as Auth Controller participant DB as User Database participant SMTP as Google SMTP Server participant Inbox as Clinician Email Inbox User->>Browser: Enters email and password Browser->>AuthAPI: POST /api/v1/auth/login AuthAPI->>DB: Fetch user record and verify Argon2 / PBKDF2 hash DB-->>AuthAPI: User record validated (MFA enabled: email_otp) AuthAPI->>AuthAPI: Generate cryptographically secure 6-digit OTP and 5-min expiry AuthAPI->>DB: Persist active_otp_code and otp_expires_at AuthAPI->>SMTP: Dispatch TLS MIME email with one-time verification passcode SMTP->>Inbox: Deliver CarePolicyGuard Security Passcode AuthAPI-->>Browser: HTTP 200 (require_otp: true, mfa_method: email_otp) Browser->>User: Display 6-digit OTP verification prompt User->>Inbox: Retrieves OTP code User->>Browser: Enters 6-digit code Browser->>AuthAPI: POST /api/v1/auth/verify-otp (email, otp_code) AuthAPI->>DB: Verify active_otp_code matches and now < otp_expires_at AuthAPI->>DB: Clear active_otp_code, generate UserSession AuthAPI-->>Browser: Issue secure session cookie / bearer token Browser->>User: Route to role-specific dashboard (Clinician / Auditor / Admin)
